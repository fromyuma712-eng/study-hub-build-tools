# study-hub build tools

大学の講義ごとに作った学習ツール（単一HTML）を1つのサイトへ集約し、認証付きで自分の端末へ配信するためのビルド基盤。本リポジトリには**ビルド・検査系のPythonコードのみ**を収録している（配信物である学習ツール本体および講義資料由来のデータは、著作権上の理由から公開対象外としている）。

## 背景

科目ごとにHTMLの学習ツールが増えるにつれ、次の3つが問題になった。

1. 原本がどこにあるか分からなくなる
2. 配信物と原本がいつの間にか食い違う
3. 生成を担当するモデル（Opus / Sonnet / Haiku）によって成果物の密度が揃わない

いずれも「人が目視で確かめる」方式では再発する。そこで**成果物の性質を機械が検査し、基準を満たさなければビルドを失敗させる**構成にした。

## 構成

| ファイル | 役割 |
| --- | --- |
| `build.py` | 原本を集約しハブページを生成する。対象は `site_config.py` の `MANIFEST` に1項目足すだけで増やせる |
| `check_notes.py` | 成果物の**密度**を検査する。1セクションあたりの項目数・平均文字数などの閾値を、既存の良質な成果物の実測分布から定めている |
| `check_coverage.py` | 成果物の**網羅性**を検査する。配布資料PDFの見出し（PyMuPDFで最大フォント行を抽出）が該当セクションに反映されているかを突き合わせる |
| `check_deploy.py` | 原本と配信物の**一致**を検査する。第三の検査器 |
| `atomicio.py` | 原子的なファイル書き出し。途中で失敗しても壊れた成果物を残さない |
| `extract_index.py` / `generate_extra_pages.py` | 見出しを抽出し、分野別インデックスページを生成する |
| `gen_coverage_manifest.py` / `gen_source_topics.py` | 網羅性検査の対象表を生成する |
| `hub_style.py` | ハブ（科目一覧・分野別・ティア表の三面）の意匠。CSS・動き・面の頭をまとめる |
| `notes_skin.py` | 各ページの原本へ、同じ意匠の層を目印付きで差し込む。何度実行しても同じ結果になり、層を外せば原本に戻る |
| `siteconf.py` / `site_config_example.py` | 個人データの読み込み口と、その見本（架空の科目） |
| `extract_pdf.py` / `vision_ocr.swift` | 講義資料を、執筆に使う文字と目で見るべき頁に分ける。文字の層が無い頁は macOS の文字認識（Vision）で起こし、図のある頁だけを縮小一覧にまとめる。段階表示の途中の頁は除く |
| `figkit.py` / `insert_figs.py` / `check_figs.py` | 講義まとめの図。SVG を色を持たない class だけで組む部品、原本へ冪等に差し込む道具、壊れ・色の直書き・文字の重なりとはみ出しを落とす検査器 |

## 個人データの分離

科目名・資料の置き場所・科目の説明文・評価文・検査の科目別例外など、授業や所属を特定しうる情報は、すべて `site_config.py` に置き、`.gitignore` で公開から外している。コードはそこを読むだけで、科目名を持たない。本リポジトリだけを取得した場合は、同じ形で架空の科目を並べた `site_config_example.py` が読まれる。

## 試験

| ファイル | 検証内容 |
| --- | --- |
| `test_atomicio.py` | **障害試験**。書き出しの各段階を強制的に失敗させ、旧内容が残ることを確認する。正常系だけでは原子性を検証したことにならないため |
| `test_build_determinism.py` | **時刻非依存の決定性試験**。同一分内の2回実行で一致しても決定性の証拠にならないため、生成時刻を変えて差分が想定箇所のみに限られることを確認する |
| `test_check_notes.py` | 検査器自体の**変異試験**。基準を満たさない検体を意図的に作り、検査器が確かに落とすことを確認する。基線確認と欠陥検出を分けて数える |
| `test_round_from_name.py` | ファイル名からの回次判定。年号・版数・ハッシュを回次と誤認しないことを確認する |

## 設計上の判断

- **検査器を信用しない** — `check_deploy.py` は当初、原本の無い項目を無言で読み飛ばして「完全に一致」と報告していた。検査器の欠陥は成果物の欠陥より発見が遅れるため、検査器自体に検体スイートを用意している。
- **決定性を実測で確かめる** — ビルドが決定的であることは主張ではなく試験で示す。
- **閾値は勘で決めない** — 密度の閾値は既存成果物の実測分布から定め、`--calibrate` で分布を再確認できるようにしている。
